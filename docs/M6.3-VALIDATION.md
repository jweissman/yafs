# M6.3 single-appliance validation

This is a hands-on check of the appliance's current local control boundary.
It uses the one normal local daemon on `127.0.0.1:7337`, with its normal
`.yafs` data directory. It proves that a host-owned desired configuration
becomes an inspectable, reconcilable virtual namespace without exposing the
host file to Yash. It does not claim a public HTTP API, a plugin marketplace,
or a third-party plugin ABI.

## Start from a known local state

For this milestone, a clean local appliance is preferable to a second,
temporary appliance. Stop the daemon, then **archive** its current state rather
than deleting it:

```sh
bun run yafsd -- stop
if [[ -d .yafs ]]; then mv .yafs ".yafs.before-m6-3-$(date +%Y%m%d-%H%M%S)"; fi
mkdir -p .yafs
```

The archived directory is recoverable and is the only state moved by this
walkthrough. To restore it later, stop the daemon, move the fresh `.yafs`
aside, and rename the archived directory back to `.yafs`.

Create the host-side desired configuration at `yafs.plugins.yaml`. It is
deliberately outside `.yafs` and outside the virtual filesystem:

```yaml title="yafs.plugins.yaml"
version: 1
plugins:
  - id: demo
    plugin: fixture
    path: demo
    config:
      files:
        hello.txt: hello
    capabilities: []
```

Use your editor to create that file, then start the one local daemon and open
its Yash client:

```sh
bun run yafsd -- start --config yafs.plugins.yaml
bun run yash
```

Every remaining command in the first section runs inside `yash`.

## 1. Inspect the configured instance

```text
plugins status
plugins plan
cat demo/hello.txt
```

Confirm that `plugins status` includes active instance `demo`, `plugins plan`
prints `[]`, and the file prints `hello`. `plugins plan` being empty matters:
it shows that daemon startup reconciled the host configuration before serving
the namespace.

Now inspect the built-in contract rather than guessing at names:

```text
plugins describe fixture
plugins describe agent
```

The fixture description identifies the provider and its configuration surface.
The agent description includes its `agent send` action and may describe a
`conversation` HTTP exposure. The latter is a design declaration only: this
validation must not open an HTTP listener.

## 2. Reconcile a configuration change

Leave `yash` with `exit`, then edit `yafs.plugins.yaml` so `hello.txt` contains
`refreshed` instead of `hello`. Do not change its id, plugin, or path.

Re-enter Yash and inspect the proposed change:

```sh
bun run yash
```

```text
plugins plan
plugins apply
cat demo/hello.txt
plugins plan
```

Confirm that the first plan contains a refresh for `demo`, the file prints
`refreshed` after `plugins apply`, and the final plan is `[]`. This is a
controlled publication step: a host-side desired-state edit does not silently
change a live virtual namespace until the operator applies it.

## 3. Check cache durability independently

Still inside Yash, run:

```text
cache put --ttl 5m validation durable
cache stat validation
```

`cache stat` should report `state: "active"`, a digest, `bytes: 7`, and an
expiry approximately five minutes in the future. Exit Yash, restart the same
local daemon, then read the value:

```sh
bun run yafsd -- restart
bun run yash -- -c 'cache get validation'
```

It must print `durable`. This checks durable local cache state; it does not
promise Redis, RESP, S3, eviction, or an externally reachable cache service.

## 3b. Force a refresh, and confirm a broken config can't hide

```text
plugins refresh demo
cat demo/hello.txt
```

`plugins refresh ID` republishes one plugin from the desired config
immediately, even when `plugins plan` already shows no diff — for forcing an
external collection (GitHub) to re-fetch on demand, not just on its
`refresh: interval`. It still prints `refreshed`.

Now hand-edit `.yafs/mounts.json` while the daemon is stopped to corrupt the
`agents` instance's `config` (if you have one configured), restart, and run
`plugins status`. The corrupted instance shows `"quarantined": true` in its
entry, and `.yafs/audit.ndjson` has one `quarantine` event for it — a broken
persisted config is visible, not silently inert.

## 4. Check the vocabulary boundary

```sh
bun run yash -- -c mounts
bun run yash -- -c 'mounts status'
bun run yash -- -c 'mount activate'
```

The first command lists VFS composition mounts. The second must fail and tell
you to use `plugins status`: plugin instances are activated and reconciled;
`union` remains the command for VFS composition. The third — the removed
`mount` (singular) lifecycle command — must fail with `Unknown command:
mount`, not a usage error: it was deleted outright, not aliased. `plugin
validate|activate|refresh|deactivate` is its sole replacement.

## Finish or restore

Stop the one local daemon when you have finished:

```sh
bun run yafsd -- stop
```

Keep the resulting `.yafs` directory if you want to inspect the journal, cache,
and generated records. To revert fully, archive this fresh `.yafs` and restore
the `.yafs.before-m6-3-*` directory you created above.

## Automated companion

`bun run validate:m6.3` runs the same core path in an entirely disposable
directory. It is useful for automated regression checking only; the single
appliance walkthrough above is the operator-facing acceptance test.
